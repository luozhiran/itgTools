# 01 接入与构建配置

## 1. 模块职责

业务模块编译时需要三个依赖：

```kotlin
plugins {
    id("com.google.devtools.ksp")
}

dependencies {
    implementation(project(":itg-ksp-annotations"))
    implementation(project(":itg-ksp-runtime"))
    ksp(project(":itg-ksp-compiler"))
}
```

`annotations` 和 `runtime` 进入业务编译 classpath；`compiler` 只能放在 `ksp(...)`，不要写成 `implementation(...)`。

根工程需要声明 KSP 插件版本，并保证 KSP 与 Kotlin 版本匹配。本仓库通过 version catalog 管理：

```toml
[versions]
kotlin = "2.1.10"
ksp = "2.1.10-1.0.29"
```

## 2. Android 功能开关

ViewBinding 场景：

```kotlin
android {
    buildFeatures {
        viewBinding = true
    }
}
```

DataBinding 场景：

```kotlin
android {
    buildFeatures {
        dataBinding = true
    }
}
```

两种 Item 同时存在时两个开关都打开。

## 3. AGP 9 / Built-in Kotlin 的生成目录

本仓库已经在 `app/build.gradle.kts` 显式注册 debug/release KSP Kotlin 输出，以便 Android Studio 识别生成类：

```kotlin
android {
    sourceSets {
        getByName("debug").kotlin.directories.add(
            "build/generated/ksp/debug/kotlin"
        )
        getByName("release").kotlin.directories.add(
            "build/generated/ksp/release/kotlin"
        )
    }
}
```

如果业务模块有其他 build type（例如 `staging`），为对应变体补充目录：

```kotlin
getByName("staging").kotlin.directories.add(
    "build/generated/ksp/staging/kotlin"
)
```

不要把 debug 生成目录注册到 `main`，否则 release 可能误用 debug 的陈旧文件。

## 4. 首次生成与验证

Windows：

```powershell
.\gradlew.bat :app:kspDebugKotlin :app:compileDebugKotlin
```

生成目录：

```text
app/build/generated/ksp/debug/kotlin/
```

release 使用 `kspReleaseKotlin`，其他变体遵循 `ksp<Variant>Kotlin`。

## 5. library 模块接入

注解必须放在执行 KSP 的同一个业务模块中。某 library 中声明了注解 Item，就在该 library 中添加三项依赖和 KSP 插件。生成类属于该 library，不会自动集中生成到 app。

## 6. 最小验收

1. KSP 任务成功执行。
2. `build/generated/ksp/<variant>/kotlin` 下出现文件。
3. `compile<Variant>Kotlin` 成功。
4. Android Studio 当前 Build Variant 与生成目录一致。
